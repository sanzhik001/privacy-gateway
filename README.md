# Маскировка от Санжика (Privacy Gateway)

Учебный проект по информационной безопасности: защитный слой между
пользователем и облачной нейросетью. Персональные и секретные данные
заменяются метками до отправки, модель получает только метки, а в ответ
пользователю возвращаются только разрешённые значения.

Маскирование снижает риск случайной утечки, но не даёт абсолютной гарантии.
Секретные и служебные данные в облачные модели отправлять нельзя.

## Как работает

1. **Политика.** Запрещённые фразы («строго конфиденциально») блокируют
   запрос целиком.
2. **Детектор Ollama.** Локальная модель Qwen на этом компьютере находит
   имена и организации, которых нет в словарях. Сама она ничего не скрывает.
3. **Маскирование.** Правила и находки детектора заменяются метками вида
   `[NAME_1#a1b2c3]`. Код в метке случаен для каждого запроса, поэтому
   поддельную метку восстановить нельзя.
4. **Исходящая проверка.** Если в запросе остался оригинал, он не отправляется.
5. **Облачная модель** (OpenAI) получает только замаскированный текст.
6. **Входящая проверка** ответа модели.
7. **Восстановление.** Метки заменяются на оригиналы, кроме паролей, ключей,
   карт, счетов и IBAN: они не возвращаются никогда.
8. **Журнал** шифруется AES-256-GCM и содержит только статус и типы находок.

Это псевдонимизация (обратимая замена), а не анонимизация. Шифрование
защищает журнал, а не сами сообщения.

## Что скрывается

- **Правилами:** телефоны, email, карты (проверка Луна), ИИН/БИН (контрольная
  сумма), IBAN KZ, счета, суммы, пароли, API-ключи и токены, логины, IP,
  документы, адреса, даты рождения, ники, номера авто, организации и банки,
  должности, идентификаторы вида `EMP-4821`, медицинские термины.
- **Имена правилами:** словарь (около 760 имён) с падежами, имя после «меня
  зовут» и должности, имя и фамилия, имя и отчество во всех падежах,
  повторы имени и его формы в других падежах.
- **Имена детектором:** редкие имена и фамилии без имени.

Намеренно не скрываются: города (`data/not_names.txt`), госорганы
(`data/public_orgs.txt`), служебные слова в диалогах («Здравствуйте», «Да»).

## Установка и запуск (macOS)

Нужны Python 3 и [Ollama](https://ollama.com).

    git clone https://github.com/<логин>/privacy-gateway.git
    cd privacy-gateway
    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    ollama pull qwen3.5:4b
    python gen_key.py              # создаёт .env и ключ журнала
    ./start.sh

Затем допишите в `.env` остальные значения по образцу `.env.example`.
Файл `.env` содержит секреты и в репозиторий не добавляется.

`start.sh` проверяет Ollama, прогоняет тесты и открывает чат только на этом
компьютере. Не запускайте `streamlit run chat.py` напрямую: так чат виден
всей сети.

Без ключа OpenAI работает провайдер `mock` (заглушка, не настоящая модель).
Если детектор включён, а Ollama недоступна, запрос не отправляется.

## Ограничения

- Детектор тоже ошибается: редкое имя, которое не нашли ни правила, ни
  модель, уходит открытым. Небольшие модели чаще пропускают имена в длинном
  тексте.
- Имя без признаков (строчными буквами, без смысла, совпадающее с обычным
  словом вроде «Роза») не распознаётся.
- Цифры словами («плюс семь семьсот один...») не распознаются.
- Модель не склоняет метки: в ответе возможен неверный падеж имени.
- Замена пароля меткой мешает задачам вида «придумай пароль надёжнее».
- Длинные числа (номер заказа) могут маскироваться как телефон: ложное
  срабатывание в безопасную сторону.
- Охранник проверяет ответ только по основным правилам, а не по всем.
- Контекст (должность, событие, место) может раскрыть человека и без имени.
- У модели нет памяти диалога: каждое сообщение обрабатывается отдельно.
- Нет полноценной аутентификации: только необязательный общий пароль.
- Потеря ключа журнала из `.env` делает журнал нечитаемым.
- Журнал обнаруживает изменение записи, но не удаление целой строки.
- Условия хранения данных у OpenAI нужно проверять по его документации.

## Статус интеграций

- OpenAI: подключён, реальный вызов проверен.
- Ollama: используется только как локальный детектор.
- Другие провайдеры не реализованы. Интерфейс `LLMProvider` в
  `src/llm_client.py` позволяет добавить их отдельным классом.
